# 生日礼物页 · 使用说明

一个给一个人做的生日礼物：他扫二维码 → 星空里出现礼物盒 → 点开 → 输入暗号 → 信一句一句浮现。

整个东西只有一个 `index.html`，没有任何外部依赖（不加载字体、不调 CDN、不联网也能跑），手机优先设计。

---

## 一、先说结论：能不能做

能，而且属于"一个人一小时"的量级。真正需要决定的只有一件事——**手机打开的那个网址放在哪**。
下面第三节给了三条现成的路，全部免费。

---

## 二、改成你自己的内容

用任意文本编辑器打开 `index.html`，搜索 `const CONFIG`，只有这一块需要动：

```js
const CONFIG = {
  to: "TO · 今天过生日的人",        // 礼物盒上方的小字，留空就不显示
  secret: ["ch"],                    // 暗号：写几个都行，任意一个都算对
  hint: "两个字母。很小声的那种叫法。",  // 输错 3 次后给的提示
  letter: [                          // 信的内容，一行一句，按顺序浮现
    "生日快乐。",
    "……",
  ],
  signature: "—— 生日快乐，我的小朋友",
  date: "2026 · 冬",
  sound: true,                       // 拆礼物和开锁时的轻音效，右上角可关
};
```

**暗号规则**：比较时会自动忽略大小写、空格、全角半角和各种标点，所以 `ch` / `CH` / `" ch "` / `ch。` 都算对。
想加拼音或别名，往数组里再加一项即可（`["ch", "小陈"]`）。

## 三、把页面放到网上（三选一）

### 方案 A：GitHub Pages（推荐，免费、长期有效）

1. 注册 github.com，右上角 **New repository**，名字随便（例如 `gift`），选 **Public**。
2. 进仓库点 **Add file → Upload files**，把 `index.html` 拖进去，Commit。
3. **Settings → Pages** → Source 选 `Deploy from a branch`，Branch 选 `main` / `(root)`，Save。
4. 等 1 分钟，网址是：`https://你的用户名.github.io/gift/`

### 方案 B：Netlify Drop（最快，30 秒，不用命令行）

1. 打开 <https://app.netlify.com/drop>
2. 把 `index.html` 所在**文件夹**直接拖进页面。
3. 立刻得到一个 `https://xxxx.netlify.app` 网址。
   （国内访问偶尔偏慢；不放心就之后绑自己的域名。免费站点闲置久了可能被回收，礼物当天用没问题。）

### 方案 C：腾讯云 COS / 阿里云 OSS（国内最快，要实名）

适合"他一定在国内、而且是微信里扫"的场景。开通对象存储 → 建桶 → 上传 `index.html` →
开启「静态网站」功能 → 把默认首页设为 `index.html` → 用给出的访问域名。

> 微信内置浏览器扫 http 链接一般能打开，但 **https 更稳**（有些手机会提示不安全）。
> 上面 A / B 都自带 https。

**临时方案（不部署）**：电脑和手机连同一个 Wi-Fi，
在 `index.html` 所在目录执行 `python -m http.server 8000`，
手机浏览器访问 `http://电脑的局域网IP:8000`。只能当天当面用，电脑不能关。

## 四、生成二维码

网址确定后，在 `tools` 目录里执行（只用 Python 标准库，不用装任何包）：

```bash
python make_qr.py https://你的网址/ qr.png --scale 20 --test
```

- 输出 `qr.png`，黑白色、四周留了 4 个模块的静区，可以直接打印。
- `--scale 20` 是放大倍数，打印用 20～30 更清楚。
- `--test` 会把它重新解码一遍做自检（正常情况下会打印「自检通过」）。

不想用命令行也可以：把网址粘到任意在线二维码工具（草料二维码等）生成，效果一样。

**打印建议**：成品不小于 2.5cm × 2.5cm，四周留白别裁掉，别用深色底。

## 五、已做好的手机适配（不用你再管）

| 问题 | 处理 |
| --- | --- |
| 手机地址栏吃掉高度、内容被顶出屏幕 | 用 `100dvh` + `env(safe-area-inset-*)` |
| iPhone 点输入框自动放大页面 | 输入框字号 18px（≥16px 不触发缩放） |
| 键盘弹出把按钮顶走 | 卡片整体居中，输入区在可视区内 |
| 下拉刷新误触、双击缩放 | `overscroll-behavior:none` + `touch-action:manipulation` |
| 弱网 / 地铁里打不开 | 单个 HTML，无外部请求，一次加载完就能用 |
| 屏幕 320px 也能看 | 字号用 `clamp()`，盒子用 `vw` 限制 |
| 晕动症用户 | 尊重 `prefers-reduced-motion`，自动关动效 |

## 六、一个诚实的提醒

密码校验在前端（页面里），**挡不住懂技术的人看源码**——它给的是"仪式感"，不是安全。
所以：放真心话没问题，别放身份证号、银行卡、住址这类东西。

## 七、文件清单

```
birthday-gift/
├─ index.html          ← 唯一要部署的文件（改 CONFIG 即可）
├─ qr-preview.png      ← 示例二维码（指向本地预览地址，仅示意）
├─ preview/            ← 三幕的效果图
├─ tools/
│  ├─ make_qr.py       ← 离线二维码生成（纯标准库）
│  └─ verify_qr.py     ← 二维码自检（重新解码验证）
```

`verify_qr.py` 会独立地把生成的码解码回来：读格式信息并校验 BCH、重建功能区、反交织、
算 Reed-Solomon 伴随式（必须全为 0）、最后比对内容。它能通过，说明这个码是真的能扫出来，
不是"看起来像二维码"。
